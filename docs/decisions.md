# Decisions and Open Questions

This is the single place for unresolved questions and settled decisions, for all the design docs. Answer open questions inline. When one is settled, move it to the decision log and update the doc it affects.

## Open questions

1. **Population and ecosystem health** (features). Population dynamics are linked to a simulation of ecosystem health, and generation-ship ecosystem failure is a failure state. What does ecosystem health measure (for example: biomass, nutrient-cycle balance, atmosphere quality, genetic diversity)? What degrades and restores it? How does it drive population growth or decline?

> TBD.

2. **Propulsion resource gates** (features). The engine types are now set (decision 19). Which resources gate each type, and in what order are they unlocked? Are solar-electric propulsion and realistic low-thrust fusion (decision 8) still in the list, as "other current or future technologies"?

> Yes, solar-electric and realistic low-thrust fusion can be added to the engine types.

3. **Construction in milestone 2 vs. milestone 4** (milestones). Milestone 2 now includes "ship design and construction", and milestone 4 still lists "construction, stations and habitats". Is the split ship construction (at the generation ship) in milestone 2, and station and habitat construction in milestone 4?

> Yes, basic ship design and construction is introduced in milestone 2.

4. **Station control** (interface). Should stations be edited through the inspector at any time (recommended), or use an "active station" model like ships? _TBD._

5. **Flows visualisation** (interface). Should resource flows be drawn on the map (route lines sized by throughput), on a diagram in the Economy screen, or both? _TBD._

6. **Content and units** (sprint 0). Should `content/` be allowed to import `math/units.ts`? For now content imports nothing. Units are the likely reason to relax this, so content could write values in convenient units (for example `mass: toKg(2.3, 't')`) or use `G0`. The narrow change would be to allow `content → math/units.ts` only, which is safe because `units.ts` has no imports. _TBD._

7. **Textbook test values** (sprint 1). The textbook cases in `orbital/*.test.ts` (Vallado, 4th ed.; Curtis, 3rd ed.) were written from memory, not copied from the books. All but one pass; Curtis 3.4's radius didn't match and was dropped, and Curtis 3.7's last velocity digit differs. Check them against the books. _TBD._

8. **Saturnian moons and Triton** (sprint 1). JPL's current satellite rows for these disagree with Horizons by up to 157° at their own epoch, while the archived 2020 rows of the same table agree. They are kept as given (decision 71). Should the 2020 rows be used instead, if the phases ever matter in play? _TBD._

9. **Ships hidden by their parent** (sprint 3). A refocus keeps the camera's direction, so a focused ship on the far side of its parent is hidden behind the parent's disc (the smoke test snaps to the ship's orbit first). Should focusing a ship choose a viewpoint where its parent doesn't hide it, for example from above its orbit plane? _TBD._

10. **Editing a non-active ship** (sprint 5b). For now a non-active ship's plan is read-only (decision 160). Should maneuver editing, and the ship controls later sprints add (targets, planning tools, docking), all need the ship to be active, or should the inspector edit any ship and only the map tools need it? _TBD._

11. **Getting the framed view back** (sprint 5b). Focusing an object on screen no longer zooms to frame it (decision 157). Should F on the object that is already focused reframe it at its framing distance? _TBD._

12. **The start view** (sprint 5b). The app starts looking down on the Earth–Moon system (decision 162), as a stopgap for the sandbox. Later scenarios may start focused on the mothership. What should the start view be once scenarios exist, and should it depend on the scenario? _TBD._

| 55  | Physics      | Time scale (S1-2)                           | Sim time `t` is TDB seconds from the scenario epoch, stored as a TDB Julian date `epochJd`. No UTC, no leap seconds; dates are shown as if UTC (about 69 s off). |
| 56  | Generation   | Planet source (S1-3)                        | JPL Tables 2a and 2b (3000 BC – 3000 AD), evaluated at the epoch and stored as elements at `t = 0` plus linear rates, Table 2b's terms included in `n`. | 57  | Generation   | Earth and the barycentre (S1-4)             | Earth is placed on the Earth–Moon barycentre's orbit (about 4,700 km from the true Earth) and the Moon orbits Earth. No barycentre nodes. |
| 58  | Physics      | Orbits on rails (S1-5)                      | A body's orbit is mean elements: elliptic elements at `t = 0`, an explicit `n`, optional linear rates for `a`, `e`, `i`, `Ω`, `ω`. `M(t) = M₀ + n·t`. | 59  | Physics      | Reference planes (S1-6)                     | Elements are given relative to a plane defined by its pole's RA and Dec in ICRF, with the node measured from the plane's ascending node on the ICRF equator (JPL's satellite convention). No plane = ecliptic. |
| 60  | Physics      | Moon accuracy (S1-7)                        | Moons use mean elements with apsidal and nodal precession only; solar perturbations are not modelled, so the Moon is off by up to 2–3°. |
| 61  | Physics      | Major / minor threshold (S1-8)              | 10¹⁹ kg. Minor bodies have no SOI. Phobos and Deimos are the only minor bodies in sprint 1. |
| 62  | Physics      | GM, not mass (S1-9)                         | Bodies store `mu` (GM, km³/s²); mass is derived as `mu / G`. |
| 63  | Architecture | Derived body fields (S1-10)                 | `major`, `soiRadius` and `childIds` are computed once by `buildBodySystem` and stored as plain data, so a saved system is self-contained. |
| 64  | Physics      | Frame transforms (S1-11)                    | A state is moved between body frames through the lowest common ancestor, never through the Sun unless that is the common ancestor, to keep docking-scale precision. |
| 65  | Physics      | Propagation (S1-12)                         | Ship states are propagated with universal variables (Vallado), `dt` reduced modulo the period for ellipses, χ by Newton's method kept inside the bracket found so far, with a Brent fallback. | 66  | Math         | General elements (S1-13)                    | `ConicElements` uses the semi-latus rectum `p` and the true anomaly `ν`. Angles are measured in the direction of motion. |
| 67  | Math         | Calendar (S1-14)                            | `math/time.ts` uses Meeus's algorithm: Gregorian from 1582-10-15, Julian before, astronomical year numbering. `calendarFromJd` rounds the time of day to the millisecond, so float noise doesn't turn 12:00:00 into 11:59:59.99999. |

| 70  | Scope        | Accuracy is not a goal (S1-17)              | The game needs a plausible solar system, not an ephemeris. | 71  | Generation   | Satellite table as given (S1-18)            | JPL's satellite mean elements are used as given: P is the sidereal period, `n = 2π/P − ω̇ − Ω̇`, `ω̇ = +2π/Pw`, `Ω̇ = −2π/Pnode` (flipped for `i > 90°`); a missing or zero period means no precession; `n` may be negative (Tethys), and the body then moves backwards along its ellipse.
